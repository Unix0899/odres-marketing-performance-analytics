The 6 pages below are generated into the PBIP by `src/powerbi_report.py` and were checked in Power BI Desktop.
The images in `dashboard/powerbi_*.png` are screenshots of those pages (synthetic data).

## Open or rebuild the report in Power BI Desktop

**Option A — open the project (recommended)**

1. Power BI Desktop → *File → Open* → `powerbi/ODRES_Marketing_Analytics/ODRES_Marketing_Analytics.pbip`.
2. If you cloned the repository elsewhere: *Transform data → Edit parameters → DataFolder* = your `powerbi\data\`
   folder (keep the final backslash). Then *Refresh*.
3. Check *Model view*: 16 relationships, DimDate marked as date table.
4. Build the visuals page by page with the tables below (fields and measures are already in the model).
5. *View → Themes → Browse* → `powerbi/odres_theme.json`.
6. *File → Save as* → `ODRES_Marketing_Analytics.pbix`. Export each page to PNG for `dashboard/`.

**Option B — if the PBIP does not open**

1. *Get data → Text/CSV*: load the 12 files of `powerbi/data/`.
2. *Model view*: create the 16 relationships listed in [DATA_MODEL.md](DATA_MODEL.md); mark DimDate as a date table
   (column `date`).
3. *TMDL view* → paste `powerbi/tmdl_measures_script.tmdl` → *Apply*: the measures are created with their formats
   and display folders.
4. Continue at step 4 of option A.

## Global design rules

- Canvas 1280 × 720, white background, 24 px margins, 16 px gaps; grid alignment.
- Colours: navy `#0D2A45` (text, headers), teal `#0F8B8D` (main series), light teal `#65B8B5`, grey `#C9D3DC`
  (comparison), amber `#C7851A` (warning), red `#B5473A` (reduce / alert). No other colours.
- Titles are questions or short statements. Maximum 6–7 visuals per page. No 3D, no pie/donut, no gauges.
- Cards: label 9 pt grey caps, value 24 pt navy bold, one-line context under the value.
- Every page has a footer text box: "Synthetic demonstration dataset — not ODRES data".
- Slicers on every page (synced): DimDate[year_month] (between), DimChannel[channel_name], DimCampaign[campaign_name].

## Page 3 — Channel & Campaign Performance

Question: *Which campaigns should we scale, maintain, optimise or reduce?*

| Visual | Type | Fields |
|---|---|---|
| 5 cards | Card | Paid spend (`CALCULATE([Total Spend], DimChannel[is_paid] = 1)`), paid CAC, non-paid revenue share, campaigns to scale / reduce |
| CAC vs revenue | Scatter | Details DimCampaign[campaign_name]; X [CAC] (log scale); Y [Won Revenue]; size [Leads]; legend = recommendation (see below) |
| Channel ranking | Table | channel_name, [Total Spend], [Leads], [CPL], [CAC], [Won Revenue], [Revenue / Spend]; rank with `RANKX(ALL(DimChannel), [Won Revenue])` |

Recommendation for the legend (calculated column on DimCampaign, same rule as `vw_campaign_performance`):

```DAX
Recommendation =
VAR Spend = CALCULATE ( [Total Spend] )
VAR Ratio = DIVIDE ( CALCULATE ( [Won Revenue] ), Spend )
RETURN
    SWITCH (
        TRUE (),
        LOOKUPVALUE ( DimChannel[is_paid], DimChannel[channel_id], DimCampaign[channel_id] ) = 0, "NON-PAID",
        Ratio >= 1.5, "SCALE",
        Ratio >= 1.0, "MAINTAIN",
        Ratio >= 0.5, "OPTIMISE",
        "REDUCE"
    )
```

`LOOKUPVALUE` is used on purpose: there is no DimCampaign → DimChannel relationship (see DATA_MODEL.md).
The SQL version also requires the lead-to-SQL rate to be above the channel average for SCALE; add that condition
if the numbers must match `vw_campaign_performance` exactly.
