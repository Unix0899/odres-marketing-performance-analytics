# Power BI data model

> Professional context based on a real ODRES Group experience. Public technical reconstruction using synthetic data.

![Data model](../proofs/proof_04_model.png)

## Design

A **star schema** with 4 fact tables at different grains sharing conformed dimensions. All relationships are
**one-to-many, single direction** (dimension filters fact). No bidirectional filter, no many-to-many.

Source files: `powerbi/data/*.csv`, produced by `src/export_powerbi_data.py` from the SQLite database.

### Why these choices

- **No relationship between DimCampaign and DimChannel.** A campaign belongs to one channel, but linking them would
  create two filter paths to the facts (ambiguity). Channel is stored on each fact instead.
- **No relationship between FactLeads and FactOpportunities.** Funnel ratios are computed from measures on each fact,
  both filtered by the same dimensions. The lead → opportunity link is kept in SQL (`vw_lead_outcomes`).
- **DimCustomer is not related to DimDate.** It would create a second path from DimDate to FactCustomerMonthly.
  "New customers by month" uses `[Customers]` on FactOpportunities (revenue date) instead.
- **Unknown campaign = member 0 "Unassigned"** rather than a blank, so the slicer shows it explicitly.
- **DimDate is marked as a date table** (`dataCategory: Time`, key column `date`) so that `DATEADD` works in the
  month-over-month measures.

## Column names vs measure names

Power BI names are case-insensitive, so a measure `Impressions` cannot sit next to a column `impressions`.
Four raw columns therefore get a model name of their own (the CSV header is unchanged, mapped with `sourceColumn`):
`impressions_count`, `clicks_count`, `sessions_count` (FactMarketingDaily) and `mrr_amount` (FactCustomerMonthly).
They are hidden; reports use the measures. `build_powerbi_project.py` refuses to build if a new conflict appears.

## Hidden columns

Technical keys (`*_id`, `*_date_key`, `month_key`, `sort_order`, `value_imputed`) are hidden: report authors use the
dimension attributes and the measures. `discourageImplicitMeasures` is on: every number comes from an explicit
measure in [DAX_MEASURES.md](DAX_MEASURES.md).
